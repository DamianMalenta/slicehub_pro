## UI i endpointy

Panel diagnostyczny ma względny link do [engineering.html](../../modules/symbiont/engineering.html). Ekran pakietu ma własny formularz nowego klucza administratora B-001, „Sprawdź udostępnienie”, „Wyczyść i zablokuj”, rzeczywisty manifest oraz czas obserwacji. Nie zwraca treści źródeł i nie zmienia konfiguracji procesu. Klucz jest usuwany z inputu, pozostaje tylko przez żądanie; brak tokenów w URL, localStorage i logach. Odpowiedzi są renderowane jako tekst, aria-live i klawiatura są częścią UI. Layout/CSP podlegają ręcznemu odbiorowi.

Oddzielny [kontrakt A](../../core/Symbiont/contracts/engineering-read-v1.json): `symbiont.engineering-read` 1.0.0, bez zmiany Bridge 1.0.0.
- POST `api/symbiont/engineering.php`: dedykowany token usługowy, snapshot.describe oraz snapshot.read.
- POST `api/symbiont/engineering-admin.php`: nowy token administratora pakietu, tylko snapshot.describe.
- Stare tokeny diagnostyczne nie działają na nowych endpointach. Nowy service token nie działa na panelu B; nowy admin nie może pobrać kodu.

Żądanie ma dokładnie protocol/version/request_id/operation/params. Params describe: package_id. Params read: package_id/snapshot_id/manifest_sha256. Żadnych ścieżek, URL, powłoki ani dodatkowych pól. Sukces ma ok=true, data.identity (host_id/environment/adapter_version), observed_at, manifest, a read dodatkowo files(path/content_base64). Błąd ma ok=false i error(code/message); niewalidowany request_id nie jest odbijany.

Manifest i kanoniczny hash określa przypięty kontrakt. Pliki są uporządkowane ASCII; hashe dotyczą oryginalnych bajtów, Base64 nie normalizuje CRLF. PHP ponownie sprawdza manifest i każdy blob względem lokalnej zatwierdzonej polityki. Nie ufa samemu hashowi dostarczonemu w pakiecie. Git SHA-1 służy związaniu z zatwierdzonym obiektem repo; SHA-256 weryfikuje transport. Nie są podpisem wydawcy.

Limity: 3 pliki, 64 KiB/plik, 128 KiB razem, response 256 KiB, request 4 KiB, timeout klienta 5 s, bez redirects. Brak/uszkodzenie pliku odrzuca pakiet atomowo, bez cichego obcięcia. Tylko environment=test. HTTP 401/403 auth, 400 schema, 404 package scope, 409 wersja/snapshot, 503 disabled/package unavailable/integrity. Brak odpowiedzi nie oznacza udanego odczytu.

## Trwałość, bezpieczeństwo i recovery

B nie otwiera żadnej bazy i nie wykonuje pobranych plików. Udostępnia przygotowany, niezmienny JSON poza docrootem; runtime PHP to inny, jawnie ograniczony zestaw plików adaptera. Przygotowanie z `ls-tree` i `cat-file` w narzędziu developerskim A czyta wyłącznie trzy zatwierdzone obiekty, nie eksportuje repo ani sekretów. B nie importuje runtime A; Node pozostaje narzędziem pilota po stronie A, nie zależnością produkcyjnego LAMP.

Źródłem prawdy runów jest osobna SQLite B-001 w A. Zgoda w A wiąże aktora, snapshot, manifest, host, rewizję i czas ważności 5 minut. Rejestracja diagnostyczna nie zastępuje tej zgody. Disconnect/cancel nie cofa odczytu i nie wyłącza PHP. Historia nie wywołuje ponownie B. Restart A przerywa run zamiast ogłaszać sukces; brak automatycznego retry.

Pilot PHP: -n, minimalne środowisko, brak sterowników DB, blokada fopen URL i funkcji procesów/sieci, open_basedir do runtime i pakietu. Readiness sprawdza te ustawienia i odmowę odczytu własnego znacznika spoza zakresu. Router blokuje m.in. ERP API, tenant_config.php, kod PHP i sam plik pakietu. To nie jest pełny sandbox OS dla dowolnego kodu. Badany kod nigdy nie jest wykonywany.

Domyślnie wyłączone. Brak pakietu/uprawnienia: odmowa i instrukcja. Timeout: niepotwierdzony wynik. Integralność: brak udostępnienia. Zmiana snapshotu: nowa kontrola administratora i zgoda, bez fallbacku. Retencja: źródła i historia pilota pozostają lokalnie do ręcznego odbioru; Ctrl+C nie usuwa danych. Instrukcja: [RUNBOOK_A, sekcja B-001](../RUNBOOK_A.md).
