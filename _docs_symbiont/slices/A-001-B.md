# A-001-B — Wszczep read-only

APPROVED 2026-09-11. Wspólny scenariusz: A-001 po stronie producenta. Stan B: [CURRENT_STATE](../CURRENT_STATE.md).

## Cel i zakres
Administrator widzi konfigurację i stan Wszczepu. Mózg sprawdza opis/diagnozę przez realne HTTP. B pozostaje osobnym repo, PHP/Vanilla JS, bez Node w runtime.

## UI
Natywny ekran integracji: wymagane uwierzytelnienie administratora, stan enabled/disabled, zakres read-only, data obserwacji, wynik lub odmowa. Nie pokazuje tokenu usługowego A->B. Osobny credential diagnostycznego panelu jest tymczasowym mechanizmem Etapu A, nie kontem pracownika. Przed OPERATE wymagane jest wpięcie ról hosta.

## Backend i kontrakt
[protocol-v1.json](../../core/Symbiont/contracts/protocol-v1.json). Wąskie describe/diagnose, constant-time token compare, limit wejścia, dokładna wersja, request_id, bez DB i bez odczytu kodu. Endpoint odmawia przy braku konfiguracji/disabled. Service token nie autoryzuje panelu administratora i odwrotnie.

## Dokumentacja
START_HERE, HOST_CONSTITUTION, GRAFT_ARCHITECTURE, UX_OPERATOR i instrukcja uruchomienia są zgodne z rzeczywistym zakresem. CORE_CONSTITUTION/WORK_PROTOCOL/BOOT_PROMPT oraz protokół są przypiętymi artefaktami A, nie lokalnymi forkami.

## Testy
A-T02/A-T04/A-T05/A-T10: PHP unit i HTTP z izolowaną konfiguracją. A-T03: realny A->PHP w testowym procesie, bez Apache i DB produkcji. A-T07: model widoku i kontrolowana weryfikacja interfejsu; sam test statusu HTTP nie wystarcza. A-T08: brak importów db_config i brak zapisów biznesowych; odłączenie mostu nie zmienia hosta. A-T09: odbiór instrukcji przez właściciela.

## Non-goals
Żadne auth fixture nie ma dostępu do właściwej bazy lub kont/PIN-ów. Nie uruchamiamy istniejącego headless runnera z auto-discovery na żywym SliceHubie. Brak operacji biznesowych, audio, telefonii i drukarek w Etapie A.
