Multi-tenant · Omnichannel · Magazyn · Dostawy · Integracje

[LOGO] · slicehub.pro · Spark 3.0 Accelerator

Problem

  • Kasa, online, magazyn i dostawy to często osobne wyspy — dane się rozjeżdżają.
  • Cena powinna być inna na sali, wynosie i dostawie; wiele systemów wciąż myśli „jedną ceną”.
  • Food cost w Excelu, menu w panelu — brak bliźniaka magazynu w czasie rzeczywistym.
  • Sieci w CEE: mieszany krajobraz POS — integracje kosztowne i kruche.

Teza

Jedna platforma = jedna prawda operacyjna. SliceHub to OS restauracji: od pierwszego ekranu klienta, przez realizację w lokalu i kuchni, po magazyn i flotę — jeden model danych, twarde reguły bezpieczeństwa finansowego i tenantowego.

  • Operatorzy, którzy płacą marżą za chaos narzędzi.

Omnichannel + koszyk

  • Brak „płaskiej ceny” — macierz cen per kanał (sala / wynos / dostawa).
  • Front nie wysyła cen ani totali — tylko SKU i ilości.
  • CartEngine na serwerze — jedyna autorytatywna kalkulacja koszyka.

Bliźniak magazynowy

  • Modyfikatory spięte z magazynem: linked_warehouse_sku + linked_quantity.
  • Waste, half-and-half × 0.5, receptury BOM.
  • Food cost i stany w kontekście recept w Studio.

Menu w czasie

  • Statusy Draft / Live / Archived.
  • Publikacja valid_from / valid_to — bez kasowania historii.
  • Soft delete dla śladu audytowego.

Logistyka

  • Jeden silnik API dla kursów i kierowców.
  • Trzy filary: zamówienie × płatność × dostawa.
  • Payment Lock + Emergency Recall — mechanizmy anty-błędowe.

Ten sam strumień zdarzeń — osobne ścieżki dostawy, retry, DLQ.

Storefront

„Okno do restauracji”, nie sztywny grid SKU. Droga produktowa: Counter + Drzwi. Wspólny renderer scen — SSOT między Directorem a sklepem klienta.

Stack

Vanilla JS + PHP 8 + MariaDB. Produkcja bez Node w runtime — niższy koszt hostingu, przewidywalne wdrożenia.

Moat

  • Konstytucja produktu v5 — m.in. drift guard docs↔kod, datowane freeze.
  • Multi-tenant jako kultura zapytań, nie dopisek.
  • Silosy danych + mosty po SKU — granice domen.

Roadmapa

  • Domknięcie Counter + Living Table (klient).
  • Pilotaże + playbook wdrożenia + QA ścieżek krytycznych.
  • Kolejni adapterzy POS pod CEE.
